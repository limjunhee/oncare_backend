## 1. 전체 흐름

```
[보호자] 이메일 입력 → "인증 메일" 클릭
   │  POST /user/email/send { email }
   ▼
[서버] 형식 검사 → 쿨다운 확인 → 6자리 생성 → Gmail 발송
       → Redis: EV:{email}=번호(5분), EVCOOL:{email}(60초)
   │
[보호자] 메일로 받은 번호 입력 → "인증 확인" 클릭
   │  POST /user/email/verify { email, code }
   ▼
[서버] EV 값과 비교 → 맞으면 EV 삭제, EVOK:{email}(30분) 저장
   │
[보호자] "가입하기" 클릭
   │  POST /user { ..., userCategoryNo: 1 }
   ▼
[서버] 보호자면 EVOK 있는지 확인 → 없으면 false, 있으면 가입 후 EVOK 삭제
```

> 프론트에서 `emailVerified`만 막는 건 우회 가능(Postman으로 바로 `/user` 호출)하므로, **서버의 6번 확인이 진짜 잠금장치**다.

## 2. API 명세

| 메소드 | 주소 | 요청 body | 응답 | 실패하는 경우 |
|---|---|---|---|---|
| POST | `/user/email/send` | `{ "email": "a@gmail.com" }` | `true` / `false` | Gmail 형식 아님, 60초 안에 재요청, 메일 발송 실패 |
| POST | `/user/email/verify` | `{ "email": "...", "code": "123456" }` | `true` / `false` | 번호 틀림, 5분 지남, 발송한 적 없음 |
| POST | `/user` (기존) | 기존 그대로 | `true` / `false` | **보호자(1)인데 인증 안 됨** ← 추가 |

## 3. Redis 키

| 키 | 값 | 수명(TTL) | 언제 생기나 | 언제 사라지나 |
|---|---|---|---|---|
| `EV:{email}` | 6자리 번호 | 5분 | 발송 성공 | 인증 성공 시 삭제 / 5분 후 자동 |
| `EVCOOL:{email}` | `"1"` | 60초 | 발송 성공 | 60초 후 자동 |
| `EVOK:{email}` | `"1"` | 30분 | 인증 성공 | 가입 성공 시 삭제 / 30분 후 자동 |

### 💡 60초 재발송 제한 원리 (`EVCOOL`)

```java
// ① 확인: 키가 살아 있으면 = 60초가 안 지남 → 거부
if (Boolean.TRUE.equals(stringRedisTemplate.hasKey("EVCOOL:" + email))) return false;
// ... 발송 ...
// ② 저장: 발송 성공 후 수명 60초짜리 키 생성 → 60초 뒤 Redis가 자동 삭제
stringRedisTemplate.opsForValue().set("EVCOOL:" + email, "1", Duration.ofSeconds(60));
```

| 시점 | Redis | `hasKey` | 결과 |
|---|---|---|---|
| 첫 발송 | 키 없음 | false | 발송 + 키 생성(60초) |
| 20초 뒤 | 키 있음(40초 남음) | true | 거부 |
| 60초 경과 | Redis가 자동 삭제 | — | — |
| 70초 뒤 | 키 없음 | false | 다시 발송 가능 |

- 타이머/스케줄러 없이 **"키가 있다 = 아직 60초 안 지남"** 으로 판단 → Redis TTL 덕분
- `Boolean.TRUE.equals(...)` : `hasKey()`가 `Boolean`(객체)이라 `null`이 올 수 있음 → NPE 방지
- 확인: `redis-cli` → `TTL EVCOOL:a@gmail.com` (남은 초, 없으면 `-2`)

### ④ `service/EmailVerificationService.java` (완성본)

```java
package oncare_backend.service;

import java.security.SecureRandom;
import java.time.Duration;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.mail.MailException;
import org.springframework.mail.SimpleMailMessage;
import org.springframework.mail.javamail.JavaMailSender;
import org.springframework.stereotype.Service;

import lombok.RequiredArgsConstructor;

@Service @RequiredArgsConstructor
public class EmailVerificationService {
    private final JavaMailSender mailSender; // 스프링이 application.properties 보고 자동으로 생성
    private final StringRedisTemplate stringRedisTemplate;  // (로그인 때 사용하는 redis와 같음)
    private final SecureRandom random = new SecureRandom();

    @Value("${spring.mail.username}")
    private String from; // 보내는 사람 = 발송용 Gmail 주소

    // [1] 인증번호 발송 메소드
    public boolean send(String email) {
        if (email == null) return false;
        email = email.trim().toLowerCase(); // 대소문자/공백 통일 (A@gmail.com 과 a@gmail.com 을 같은 키로)
        if (!email.matches("^[^\\s@]+@gmail\\.com$")) return false; // Gmail 형식이 아닐 경우 false
        if (Boolean.TRUE.equals(stringRedisTemplate.hasKey("EVCOOL:" + email))) return false; // 60초동안 발송을 제한

        String code = String.format("%06d", random.nextInt(1_000_000)); // 000000 ~ 999999 (앞자리 0 유지)
        try {
            sendMail(email, code);
        } catch (MailException e) {
            return false; // 발송 실패 시 Redis 에 아무것도 저장하지 않음 → 바로 다시 시도 가능
        }
        stringRedisTemplate.opsForValue().set("EV:" + email, code, Duration.ofMinutes(5));     // 인증번호 5분
        stringRedisTemplate.opsForValue().set("EVCOOL:" + email, "1", Duration.ofSeconds(60)); // 재발송 쿨다운 60초
        stringRedisTemplate.delete("EVOK:" + email); // 재발송하면 이전 인증 완료 상태 취소
        return true;
    }

    // [2] 인증번호 확인 메소드
    public boolean verify(String email, String code) {
        if (email == null || code == null) return false;
        email = email.trim().toLowerCase();
        String saved = stringRedisTemplate.opsForValue().get("EV:" + email); // 5분 지났으면 null
        if (saved == null || !saved.equals(code.trim())) return false;

        stringRedisTemplate.delete("EV:" + email); // 한 번 쓴 번호는 폐기
        stringRedisTemplate.opsForValue().set("EVOK:" + email, "1", Duration.ofMinutes(30)); // 30분 안에 가입 완료
        return true;
    }

    // [3] 인증 완료 여부 (회원가입 시 UserService 에서 호출)
    public boolean isVerified(String email) {
        if (email == null) return false;
        return Boolean.TRUE.equals(stringRedisTemplate.hasKey("EVOK:" + email.trim().toLowerCase()));
    }

    // [4] 가입 완료 후 인증 기록 삭제 (같은 인증으로 두 번 가입 방지)
    public void clear(String email) {
        if (email == null) return;
        stringRedisTemplate.delete("EVOK:" + email.trim().toLowerCase());
    }

    // 실제 메일 발송 (내부용)
    private void sendMail(String to, String code) {
        SimpleMailMessage message = new SimpleMailMessage();
        message.setFrom(from);
        message.setTo(to);
        message.setSubject("[온케어 스케줄] 회원가입 인증번호");
        message.setText("온케어 스케줄 회원가입 인증번호는 [" + code + "] 입니다.\n"
                      + "5분 안에 입력해주세요.\n\n본인이 요청하지 않았다면 이 메일을 무시하셔도 됩니다.");
        mailSender.send(message);
    }
}
```

| 포인트 | 이유 |
|---|---|
| `SecureRandom` | 일반 `Random`보다 예측이 어려움 (인증번호용) |
| `%06d` | `random.nextInt(1_000_000)`이 `4521`이면 `004521`로 6자리 유지 |
| 발송 **성공 후** Redis 저장 | 메일이 실패했는데 쿨다운만 걸리는 상황 방지 |
| `toLowerCase()` | 프론트 정규식은 `/i`(대소문자 무시)라서 서버도 맞춰 줌 |
| `EV` 사용 후 삭제 | 같은 번호 재사용 방지 |

## 5. 테스트

| # | 방법 | 기대 결과 |
|---|---|---|
| 1 | 서버 실행 | 메일 관련 에러 없이 기동 (`JavaMailSender` 빈 생성 실패 시 ②③ 확인) |
| 2 | `Invoke-RestMethod -Uri http://localhost:8080/user/email/send -Method Post -ContentType "application/json" -Body '{"email":"내주소@gmail.com"}'` | `True`, 메일 도착 (스팸함 확인) |
| 3 | 바로 다시 2번 실행 | `False` (쿨다운) |
| 4 | `redis-cli` → `GET EV:내주소@gmail.com` / `TTL EVCOOL:내주소@gmail.com` | 6자리 / 60 이하 숫자 |
| 5 | `/user/email/verify` 에 틀린 번호 → 맞는 번호 | `False` → `True`, `EXISTS EVOK:...` = 1 |
| 6 | 인증 없이 Postman으로 보호자 `/user` 가입 | `false` (서버 잠금 확인) |
| 7 | 브라우저에서 보호자 가입 전체 흐름 | 가입 성공, `EVOK` 키 삭제됨 |
| 8 | 관리자/센터 가입 | 이메일 인증 없이 기존대로 동작 |

## 6. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `AuthenticationFailedException` / 535 | 앱 비밀번호가 아니라 일반 비밀번호를 넣음, 또는 띄어쓰기 포함 |
| `MailConnectException` / timeout | 학교 네트워크가 587 차단 → 핫스팟으로 확인, 계속 막히면 Gmail API(OAuth) 고려 |
| `JavaMailSender` 빈 없음 | `spring-boot-starter-mail` 누락 또는 Gradle Refresh 안 함 |
| `Could not resolve placeholder 'spring.mail.username'` | `application.properties`에 ③ 설정 없음 (병합 때 덮어써졌는지 확인) |
| 메일이 안 옴 | 스팸함 확인. 새 계정 첫 발송은 스팸으로 가기 쉬움 |

## 7. 나중에 여유 있으면 (선택)

| 항목 | 내용 |
|---|---|
| 확인 시도 횟수 제한 | 5분 동안 6자리를 무작위 대입 방지 → `EVTRY:{email}` 카운트, 5회 넘으면 `EV` 삭제 |
| 동시 요청 방지 | `hasKey` + `set` 대신 `setIfAbsent("EVCOOL:"+email, "1", 60초)` 한 줄 (실패 시 `delete`로 풀어주기) |
| 실패 이유 구분 | `boolean` 대신 `"OK" / "INVALID" / "COOLDOWN" / "FAIL"` 반환 → 프론트 메시지 세분화 |
| 남은 시간 표시 | 프론트에서 60초 카운트다운 후 "재발송" 버튼 활성화 |
| HTML 메일 | `MimeMessageHelper`로 로고·버튼 있는 메일 |
